# 可选 Skill 衔接：按实际安装与项目规则使用

这张表是能力路由，不会安装、复制或授予任何外部 Skill 权限。每次先确认新电脑上**确实安装并可用**、其依赖满足、目标项目允许使用；再读取该 Skill 当前的 `SKILL.md`。同名 Skill 可能来自不同来源，不凭名称猜行为。

| 工作节点 | 可选能力 | 何时适合 | 基础做法仍是什么 |
| --- | --- | --- | --- |
| 需求与技术方案不清 | 项目已有的需求澄清/设计 Skill | 需要拆清规则、边界、接口或跨服务方案 | 先对齐真实验收和负责人，记录未决项 |
| Bug 根因 | `investigate` 类 Skill | 有可复现现象、日志或请求链 | 按[排障卡](bug-fixing.md)建立证据和反例 |
| 技术方案边界与开发 CR | 同包 `java-change-review` | 方案待审或已有明确 diff 与目标基线 | 审最小方案、冻结范围、核对本次回归 |
| 测试视角 CR | `code-review-test` | 已安装且其仓库/依赖/范围协议适用；需要需求匹配、缺陷候选与回归范围 | 提供明确 repo、base/target、需求版本；按其自身证据门槛执行 |
| 用例设计 | 项目已有 `test-case` 等 | 有评审过的需求与独立预期来源，项目接受其输出格式 | 用[自测矩阵](self-test-handoff.md)识别需证明的行为 |
| 接口自动化 | 项目已有 `generate-pytest` 等 | 已有接口契约、测试数据与清理策略 | 先证明字段、数据和业务断言，不凭 PRD 猜接口 |
| 浏览器验收 | `qa` / `qa-only` 类 Skill | 页面可运行、登录与测试数据合规 | 同一次操作关联页面、Network、后端结果 |
| 交付文档 | 项目已有文档更新 Skill | 代码已定稿，接口/架构文档需要跟随 | 只更新与实际 diff 相符的私有文档 |

本机现有的 `code-review-test` 与测试用例/pytest 相关 Skill 对其自身平台的资料、目录和证据格式有约束；**不能直接迁移为新公司的强制流程**。同包 `java-change-review` 可以独立做方案和代码审查；完整测试视角扩展只有在目标环境可用时才调用。

任何外部 Skill 涉及测试环境写入、缺陷提报、消息、发布或远端变更时，按新公司项目规则和当前任务授权处理；调用 Skill 本身不等于授权这些操作。
