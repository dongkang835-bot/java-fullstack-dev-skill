# 资深质量闭环：让初学者交付可评审的全栈改动

本页用于纯小白拿到真实需求或 Bug 后。AI 负责执行定位、设计、实现与验证；使用者提供业务目标、项目授权和无法从仓库推得的规则。AI 用这次改动的实际代码解释必要概念，不把学习计划设成开工前置。目标是交付达到资深前后端工程师评审标准的代码，质量由证据证明。按本次改动风险选择深度，局部文案或样式改动不需要数据库与并发分析。

## 一、先定义正确结果

从需求、验收标准、接口契约或负责人确认提取独立于当前代码的预期。每个受影响行为写清：谁在什么状态下做什么，成功后用户和数据分别看到什么；参数错误、无权、重复、冲突或下游失败时应如何表现。已有实现只能说明现状，不能充当需求的唯一正确性来源。规则冲突或缺失且会改变代码方案时，集中提出具体问题；其余可独立工作继续做。

用一张小表把证据闭合，简单任务可压成几行：

| 验收行为与预期来源 | 当前入口/数据链证据 | 改动点与关键不变量 | 验证方法、实际结果 |
| --- | --- | --- | --- |
| 谁、何时、应看到什么 | 页面/API → 后端 → 数据或下游 | 什么必须始终成立 | 哪个断言证明；未执行写 `not run` |

**不变量**是即使重试、并发或失败也必须成立的业务事实，例如“用户只能改自己的记录”“同一请求不能重复产生副作用”。只写本次真实受影响的不变量，别把通用风险清单复制进任务。

## 二、像资深工程师一样选最小方案

在当前仓库找最接近的实现和测试，追完整路径：页面事件与参数 → API/网关 → Controller 与 DTO → Service 的权限、状态和事务 → Mapper/SQL、缓存、消息或外部服务。标出已运行验证与仅由源码推断的结论。对同一功能的列表、详情、修改、导出等入口，检查它们是否共享本次不变量。

实施前给出短方案：改哪些文件、为何放在这一层、如何保持旧调用方与历史数据兼容、失败会留下什么状态、怎样证明正确。若准备新增抽象、依赖、表、服务或跨服务状态，使用 `java-change-review` 比较复用现有路径与新增方案的具体收益和成本。业务规则未知时，不用新框架填补空白。

## 三、实现时守住真实边界

- **接口边界**：前后端核对字段名、类型、空值、枚举、时间/金额、错误码和旧调用方；前端显隐不能代替后端权限。
- **数据边界**：在实际查询和写入路径核对对象/租户范围、软删除、唯一性、索引与历史数据；手写 SQL 要看最终条件。
- **一致性边界**：确认事务真正生效的代码路径；数据库、缓存、消息和 HTTP 副作用的提交与失败顺序要明确。重复或并发请求按业务不变量决定是否需要约束、版本条件或幂等键。
- **运行边界**：本次改动涉及批量或远程调用时，查输入上限、循环查询、超时、重试、资源释放与可定位的日志；用实际规模或失败条件决定优化深度。

以上是检查方向，不是要求每次都引入一套机制。沿项目现有约定写代码，避免无关重构。遇到不熟悉的 Java/Spring 语义，AI 应核对目标版本和本次运行路径，再用一两句话解释它为什么影响这次改动。

## 四、用反例证明，而非凭代码看起来正确

为每个验收行为选择最小充分的验证层：纯规则用单元测试；请求与错误语义用 API/契约测试；SQL、约束与回滚用隔离数据库集成测试；页面消费用真实页面与同次 Network；跨服务副作用用受控集成链路。先找能让旧实现失败、让新实现通过的关键断言；若旧实现没有可复现问题，仍须用独立预期验证新行为。只针对受影响的失败、无权、重复、并发和兼容路径补验证，不机械跑全排列。

记录测试命令、环境、目标提交、业务断言和结果。Mock 要说明替换了哪一段，不能把 Mock 通过写成真实数据库或下游通过。编译、lint、测试进程退出 0 各有证明范围，不能代替对业务结果的断言。环境不可用时保留 `not run` 和具体缺口，不把推断写成 PASS。

## 五、交付前做一次反向审查

冻结本次仓库和 diff 范围，逐处重读完整方法及直接调用方；检查是否删掉了既有权限、校验、锁、异常映射或资源释放。对每个疑点问：本次是否引入、合法输入能否到达、上游是否已有保护、错误是否可观察？能执行就用定向测试或受控复现。审查结果区分已确认问题、待验证疑点与覆盖缺口；修复后按新代码重新验证。详细审查走 `java-change-review`。

## 给初学者的交接说明

交付时用简短语言说明三件事：本次最关键的不变量是什么，代码在哪一层保证它，哪条测试或运行证据证明它。再说明最重要的一个未覆盖风险及需要什么条件才能验证。让开发者能够向评审人解释，而不要求先掌握整个 Java 技术栈。

若需求正确性来源、授权、目标版本或关键运行证据仍缺失，不宣称达到资深工程质量；明确已经完成的部分和下一步最有区分力的证据。
