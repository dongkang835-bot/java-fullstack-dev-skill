# 拉仓后的一页架构盘点

目标是能解释一个真实页面操作如何经过服务、数据库和中间件。先盘点全貌，再为首个任务深追相关链路；不要把目录名当成架构结论。

## 盘点顺序

1. **仓库边界**：列主仓、子模块、独立仓、前端和后端。每个仓库记录分支/提交、维护人或团队、构建入口。查 README、`AGENTS.md`、CI、部署文件和模块 POM/Gradle。
2. **模块依赖**：从 POM 的 `<modules>`/依赖、Gradle settings、前端 workspace 配置找模块关系。区分 API/Feign、Service、domain、common、web；不因名叫 `common` 就推定所有服务共享运行时。
3. **请求入口**：选一个真实前端 API，追网关/BFF、Controller、权限/参数、Service、持久化或外部调用。结合代码与运行证据标注同步/异步和错误返回路径。
4. **数据与中间件**：搜依赖和配置**键名**识别候选；再找实际 Bean、调用方、消息监听器、Mapper、迁移脚本与部署清单确认是否启用。项目可以使用 MySQL/PostgreSQL/OceanBase、Redis、Kafka/RocketMQ、Nacos/Apollo、对象存储或其他组件；任何一种都不能仅凭这份清单断言存在。
5. **运行边界**：画出本地进程、容器和共享 dev/test 的位置；确认哪些命令会写共享数据、注册服务、消费消息、跑定时任务或触发迁移。没有证明前不要试写。

## 中间件与数据库要问的具体问题

| 对象 | 需要核对的事实 |
| --- | --- |
| 关系数据库 | 方言、Schema 管理、连接池、事务管理器、隔离/唯一约束、读写分离、慢查询/索引、测试数据隔离 |
| Redis/缓存 | key 命名与 TTL、缓存一致性、序列化格式、锁是否跨实例、故障时回退 |
| MQ/事件 | Topic/Tag、生产者与消费者、确认方式、重试/死信、幂等、顺序、最终一致性的观察点 |
| 配置中心/服务发现 | Profile/Namespace、配置优先级、服务名、启动注册行为、环境边界 |
| 网关/BFF/认证 | 前端代理到哪一层、Token 与会话、功能权限与对象/租户数据范围、错误映射 |
| 外部服务/文件存储 | 超时与重试、凭据来源、上传/下载权限、失败恢复与审计 |

## 产出格式（仅私有）

```md
代码基线：<每仓库分支与提交>
目标业务入口：<页面/请求/用户动作>
调用链：页面 → API/网关 → Controller/BFF → Service → DB/MQ/外部服务
模块图：<模块/仓库及边界，附证据文件>
运行图：<本地/容器/共享环境中的依赖>
技术栈：<JDK/Spring/ORM/前端/数据库/中间件，分别附证据>
本地启动：<可执行命令及实际结果>
未知项：<需要团队回答的问题；影响哪些任务>
```

对每条结论标 `已验证`、`源码推断` 或 `待确认`；知识库与当前代码不一致时记录双方版本和证据。完整请求追踪可转到同包 `java-fullstack-dev/references/code-tracing.md`；首个需求只需深入本次涉及的模块和直接依赖。
