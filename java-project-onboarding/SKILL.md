# Java 项目入职与环境落地

目标是让新电脑上的一个真实项目完成“代码可取、依赖可装、最小服务可启动、调用链可解释”。先读取当前仓库 `AGENTS.md`、README、CI、构建文件和团队环境文档；此 Skill 不预设 JDK、Spring、数据库、中间件或审批流程。公司仓库地址、凭据、配置值和项目画像只留在允许的私有位置。

## 执行顺序

1. **电脑与权限**：识别 OS/架构、现有工具、公司提供的 VPN/代理/证书、Git 主机访问和 IDE。可运行 `python3 scripts/workstation_doctor.py [--project <目录>]` 生成只读盘点；输出是私有材料。缺 Python 时用[手工检查](references/day-one.md)。不读取或打印密钥值。
2. **取代码**：确认团队给的仓库、目标分支和克隆方式；查 `.gitmodules`/Git LFS/多仓关系。用项目固定的子模块提交，不擅自更新到远端最新。核对每个实际仓库的 HEAD 与工作区状态。
3. **适配安装**：从 POM/Gradle、Wrapper、CI、Node 版本文件和锁文件确定版本，再按[安装与验证操作页](references/install-recipes.md)安装。Maven/Gradle 有 Wrapper 时优先使用；数据库、Redis、MQ、配置中心和容器只安装当前任务确需的部分。安装源与凭据遵循公司渠道。
4. **最小启动**：先验证构建，再启动一个目标服务和需要的前端；确认依赖指向、健康检查、只读请求与页面到接口的一次调用。编译成功、进程存活和业务可用分别记录。
5. **架构画像**：按[架构盘点](references/architecture-intake.md)画出服务、数据库、中间件、配置与调用边界。用当前源码核对文档，标明已验证/推断/待确认。把结果填入 [项目画像模板](assets/PROJECT_CONTEXT.template.md) 的副本，保存到新项目私有位置。

## 收尾结果

交付一份私有的“工作站与仓库基线”：工具版本及来源、缺项与安装结果、仓库及提交、配置获取渠道、最小启动命令与实际结果、架构图/调用链、阻塞点。未获知真实项目版本前，不给出固定的 `brew install`、`winget install` 或数据库初始化命令；先给可执行的检查与待确认的版本，再补适用命令。若用户已授权安装并且来源、版本确定，直接执行并验证。

环境可运行后，开发需求使用同包的 `java-fullstack-dev` Skill；审查、自测与提测按新项目规则和该 Skill 的相应参考文档执行。
